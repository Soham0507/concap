## Feature: Universal Meeting Invitation Service

### Objective

Implement a provider-independent invitation system that works for **Google Meet, Microsoft Teams, Zoom, and any future meeting provider** without relying on Google Gmail, Microsoft Outlook, or Zoom email permissions.

### Current Problem

The current implementation attempts to send invitations through the connected provider account. This causes failures such as:

* "This workspace has not connected Google Meet"
* Missing Gmail send permissions (`gmail.send`)
* Provider-specific OAuth limitations
* Different logic for each meeting platform

This tightly couples invitation sending with the meeting provider.

### Required Solution

Create a **Universal Invitation Service** that sends emails from our application's backend instead of the user's connected account.

The meeting provider should only be responsible for creating or importing the meeting. Once the meeting exists, invitation emails should always be sent by our backend email service.

### Supported Email Providers

The system should be designed so that any backend email provider can be configured, such as:

* SMTP
* SendGrid
* Amazon SES
* Mailgun
* Resend
* Postmark

The email provider should be configurable through environment variables.

### Invitation Flow

1. User clicks **Send Invitation**.
2. Backend validates the meeting exists.
3. Backend fetches meeting information.
4. Generate an email containing:

   * Meeting title
   * Organizer
   * Date
   * Time
   * Time zone
   * Meeting platform
   * Join meeting URL
   * Meeting ID (if available)
   * Passcode (if available)
   * Description
5. Generate an **ICS calendar invitation**.
6. Attach the ICS file to the email.
7. Send the email using the configured backend email service.
8. Return success or failure to the frontend.

### Email Template

The email should include:

* Company branding
* Meeting title
* Meeting date and time
* Join Meeting button
* Meeting link
* Meeting ID
* Passcode (if applicable)
* Organizer information
* Calendar (.ics) attachment

### ICS Calendar Support

Generate a valid RFC 5545 (.ics) calendar file including:

* UID
* DTSTART
* DTEND
* SUMMARY
* DESCRIPTION
* LOCATION (meeting URL)
* ORGANIZER
* ATTENDEE(S)
* Timezone

The calendar invite should work with:

* Google Calendar
* Microsoft Outlook
* Apple Calendar
* Thunderbird
* Samsung Calendar

### Provider Independence

The invitation service must work identically for:

* Google Meet
* Microsoft Teams
* Zoom
* Imported meetings
* Custom meeting URLs
* Future meeting providers

The invitation system must **never** require checking whether Google, Zoom, or Microsoft accounts are connected before sending emails.

### Backend API

Create a generic endpoint such as:

POST /api/meetings/{meetingId}/invite

Request Body:

* recipient emails
* optional custom message

The backend should automatically determine the meeting details and send invitations.

### Error Handling

Provide clear error responses for:

* Meeting not found
* Invalid recipient email
* Email provider unavailable
* Failed email delivery
* Invalid meeting data

Do not return provider-specific errors such as:

* "Workspace has not connected Google Meet"
* "Zoom account not connected"
* "Teams account not connected"

These provider connection states should not affect invitation sending.

### Logging

Log:

* Meeting ID
* Sender
* Recipients
* Email provider response
* Delivery status
* Failure reason
* Timestamp

### Future Extensibility

The service should be built so additional providers (e.g., Webex, GoTo Meeting, Cisco Meeting, Slack Huddles) can be added without changing the invitation logic.

The invitation module should remain completely independent of the meeting provider integration.

### Expected Outcome

A single, unified invitation system that sends branded emails with calendar invitations for all meeting platforms, eliminating the need for provider-specific email permissions and providing a consistent experience across Google Meet, Microsoft Teams, Zoom, and future integrations.
