We are building an AI-powered Conversation Intelligence platform for expos, meetings, networking events, and business discussions.

Current Status:
We already have:

* audio recording/upload
* transcription
* dashboard UI
* conversation list
* summary cards
* lead scoring UI

But currently the system only does:
Audio → Transcript → Simple Summary

We now want to build a REAL AI conversation intelligence pipeline.

====================================================
MAIN PRODUCT GOAL
=================

A user may record 2–3 hours of continuous audio during:

* expos
* business networking
* client meetings
* sales discussions
* conferences

During those 2–3 hours:

* multiple people talk
* topics change
* new visitors come
* conversations end/start continuously

The AI system must automatically:

1. transcribe audio
2. detect speakers
3. detect when a new conversation starts
4. split long transcripts into separate conversations
5. analyze each conversation independently
6. generate summaries
7. extract business intelligence
8. generate lead scores
9. create structured CRM-ready data
10. support semantic AI search later

====================================================
CURRENT PROBLEM
===============

Right now the system treats the entire 2-hour transcript as ONE conversation.

This is incorrect.

We want AI to automatically detect:

* when one visitor leaves
* when another visitor starts talking
* when topic changes
* when discussion context changes

The AI must intelligently split conversations automatically.

======================

The MOST IMPORTANT feature is:

AI Conversation Segmentation

We need an AI engine that automatically detects:

* conversation boundaries
* visitor changes
* topic changes

====================================================
HOW CONVERSATION SEGMENTATION SHOULD WORK
=========================================

The segmentation engine should use multiple signals:

1. Speaker Changes
   Example:
   Speaker A + Speaker B
   ↓
   Speaker A + Speaker C

This likely means a new visitor joined.

---

2. Silence Detection
   Example:
   15–20 seconds silence

This may indicate one conversation ended.

Use:

* ffmpeg silence detection
* pydub

---

3. Topic Change Detection
   Example:
   Discussion about CRM pricing
   ↓
   Discussion about manufacturing machinery

This is likely a new conversation.

Use:

* embeddings
* cosine similarity
* sentence-transformers

---

4. Semantic Context Change
   Detect:

* different products
* different industries
* different discussion intent

====================================================
STRUCTURED TRANSCRIPT FORMAT
============================

Instead of plain transcript text:

"Hello sir nice meeting you"

Store structured transcript like:

[
{
"speaker": "Speaker 1",
"start": 0,
"end": 12,
"text": "Hello sir nice meeting you"
},
{
"speaker": "Speaker 2",
"start": 13,
"end": 20,
"text": "We manufacture CRM systems"
}
]

This structured transcript becomes the AI input.

====================================================
IMPORTANT IMPLEMENTATION RULE
=============================

DO NOT process entire 2-hour audio at once.

Instead:

2-hour audio
↓
Split into 2–5 minute chunks
↓
Process chunks independently
↓
Merge intelligently
↓
Run segmentation engine

This is required for:

* scalability

* faster processing
* AI cost reduction
