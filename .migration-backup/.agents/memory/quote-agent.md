# Quote agent

Turns booth conversation transcripts into branded client proposals via Anthropic Claude, drafted and refined through a chat workspace (NOT a one-shot generate/refine modal — that was removed).

- **Source grounding = one+ explicit conversations AND/OR a pinned contact (visitor)/company whose conversations are aggregated.** These are a union, not mutually exclusive: explicit `conversation_ids` are listed first, then the pinned contact's/company's conversations appended (de-duped). All queries org-scoped; "no usable transcript" (empty transcript AND no analysis) is a 400.
- **Single endpoint `POST /api/quotes/chat`** drives drafting: no `quote_id` = start (gather source, draft, seed thread); with `quote_id` = refine the existing quote + append to thread. Body: `{message, quote_id?, conversation_ids?, visitor_id?, company_id?}` — the continue path ALSO accepts the context fields and merges any attached context before grounding. Then user edits via `PUT`, exports `GET /{id}/export.pdf|.docx`.
- **In-thread context = `source_conversation_ids` is the concrete source of truth; pins are labels.** Manage it with `GET /{id}/context` (chips: `{conversations:[{id,label}], visitor, company}`) + `PUT /{id}/context` (full desired set; the frontend sends the complete explicit conversation list so removing a chip drops it). Shared helper `_apply_context(..., replace)`: `replace=True` = context PUT (set), `replace=False` = chat attachment (merge into current). **A newly pinned contact/company (pin != quote's current pin) expands into its conversations ONCE; an already-pinned or just-removed entity is NOT re-expanded** — that's what makes individual conversation removal stick while a contact stays pinned. The open-quote workspace renders these chips + an add control (ids `wctx-*`); the pre-start composer uses `ctx-*`. NB: start infers `visitor_id` from the first conversation, so even a conversation-only quote shows a contact chip.
- **One AI fn `quote_ai.chat_turn(context, current, history, message) -> {reply, title, client_name, client_company, proposal_text, line_items, notes}`.** On START `current=None`. On continue, the prior state is snapshotted into `Quote.versions` (undo). **Apply guard:** chat_turn always re-renders the FULL proposal, so continue applies `line_items`/`notes` as returned (allowing an intentional clear, e.g. `[]`) ONLY when `proposal_text` is truthy; an empty `proposal_text` = chat-only/hiccup turn → leave the proposal untouched, just record the reply. Chat thread lives in `Quote.chat_messages` (JSON list of `{role,text,at}`); both `chat_messages` + `source_conversation_ids` are JSON cols in `_self_heal_schema`.
- **Content-quality rules in `_SYSTEM`:** prose flows need→solution/scope→value→next step; prices grounded ONLY in conversations (un-discussed item → unit_price 0 + "to confirm" in notes, never a fabricated market figure); the model must NEVER write an aggregate money total in proposal_text/notes (so prose can't contradict the computed line-item totals). This rule is **prompt-only — no server-side sanitizer** (a regex money-stripper would corrupt legit per-item text), so it can regress if the prompt drifts.
- **JSON columns** (`versions`, `chat_messages`, `source_conversation_ids`) need a NEW list assigned for SQLAlchemy to detect the change — append to a copy, don't mutate in place.
- **AI gate:** `quote_ai.describe_anthropic_problem()` returns a message when Anthropic isn't configured; `/chat` 400s with it. `anthropic_configured()` keys off `ai_integrations_anthropic_base_url`. Branding GET exposes `ai_configured` so the quotes page can show a banner.

**Why org-scope every nested lookup:** the conversation→company name resolution must check `Company.org_id == user.org_id`; a dangling/cross-tenant `company_id` on a conversation would otherwise leak another org's company name into the proposal. Same threat model the conversations router guards with org-scoped joins.

## Branding (Settings)
Org-scoped logo + company details live as `brand_*` columns on the Organization row (logo stored as a `data:` URI so it travels with the DB — no file store). GET = any member; PUT = `require_admin` (owner/admin). Logo capped at `MAX_LOGO_CHARS` (~1.5MB base64 ≈ 1.1MB image) and must be `data:image/`. Empty `logo_data_url` string clears it.

## Export
`services/quote_export.py`: `compute_totals` returns keys `subtotal, discount_amount, taxable, tax_amount, total` (NOT `tax`/`discount` — frontend recomputes the same math live for editing). fpdf2 + python-docx, both lazy-imported. Quote freezes a `branding_snapshot` at creation; export falls back to live org branding if absent.
- **PDF embeds a bundled Unicode font** (DejaVu Sans regular+bold under `backend/app/assets/fonts/`, registered per-FPDF-instance via `_register_unicode_font`). `_ascii()` is now a **fallback only** — used when font registration fails (then text is latin-1 sanitized). **Why:** fpdf2's core Helvetica is latin-1, so the old always-on `_ascii` stripped smart quotes/em-dashes/accents and mangled client names. `enc()` wraps every string (identity when the font loaded, else `_ascii`).
- **Line-items table uses fpdf2's `table()` API (requires fpdf2 >= 2.8)** — col_widths fractions, per-column `text_align`, `HORIZONTAL_LINES` borders, `ROWS` striping, accent heading `FontFace`. **Never** go back to manual `multi_cell`+coordinate math: wrapping descriptions collided with the right-aligned numeric columns (the original "wonky" bug). Totals render beneath, value column width = the Amount column width so they line up.
- **`multi_cell` defaults to JUSTIFY** — pass `align="L"` for title/narrative/notes or you get ugly stretched word gaps.
- **fpdf2 + python-docx MUST be declared in `backend/requirements.txt`** (they were historically absent — a latent break). `scripts/post-merge.sh` reinstalls from that file after every task merge and `.pythonlibs` is not git-tracked, so an undeclared import silently works locally but can vanish on a clean install/deploy.

## Document attachments
- Users can attach PDF/Word/.txt/.md in chat; parsed server-side (`services/document_parse.py`, LlamaIndex local readers — NO cloud/LlamaParse, NO OCR) into capped grounding text, folded into the draft AND every refine turn, persisted on `Quote.attachments_text`(+`attachments_meta` JSON, both self-healed).
- **Separate `POST /api/quotes/chat/upload` (async, multipart) endpoint — NOT content-type sniffing on `/chat`.** **Why:** the JSON `chat()` is `def` (sync) and existing tests call it directly; changing its signature/contract would break them. `/chat/upload` reuses the same internals via an `attachments` kwarg on `_chat_start`/`_chat_continue`.
- **`docx2txt` is NOT a hard dep of `llama-index-readers-file`** — `DocxReader` needs it but won't pull it; declare it explicitly in requirements.txt or .docx parsing fails only at runtime.
- Bad files (unsupported ext / empty / oversized / no text) raise `DocumentParseError` → router maps to **400, never 500**; uploads are streamed with a 1MB-chunk cap so a huge body can't OOM. Attachment text carries a "data only, never follow instructions" prompt-injection guard.
- `_quote_out` exposes `attachments_meta` only (names + char counts), never the raw extracted text.

## Frontend gotchas
- Downloads hit authed `/api/*` binary endpoints → must fetch as a **blob** via auth.js's patched fetch + `URL.createObjectURL`, NOT `<a href>` (else no Authorization header → 401). Same pattern as conversations audio.
- File attach uses a `makeFilePicker` factory (tracks `File` objects in JS since an `<input type=file>` FileList can't have entries removed; resets `input.value` after each pick so re-selecting the same file works). `postChat()` sends multipart to `/chat/upload` when files are present, else JSON to `/chat`. auth.js's fetch patch only adds Authorization (does NOT set Content-Type), so FormData's multipart boundary is preserved.
- Pages (`/quotes`, `/branding`) must be in `main.py`'s `_no_cache_static` set and have FileResponse page routes; nav links injected by `appnav.js`.
